# 院内補綴制作ダッシュボード

院内補綴制作の月別・種類別本数、医院別構成、院内原価、外注相当額、推定削減額、CAD/CAMの保険点数表、リテーナー4セット症例の制作ルート比較を表示するGitHub Pages向け静的BIです。

## 外注先別単価（2026-08-26改定）

メイン画面の「外注価格」で、成田デンタル・東洋デンタルを切り替えて再計算できます。「外注単価比較」タブでは両社料金を品目別に比較できます。未提示の単価は未設定として集計から除外します。

e.maxは院内原価4,555円（材料費4,180円＋労務費375円）で推定削減額を再計算します。

## 保険点数・診療報酬

「保険点数・診療報酬」タブでは、令和8年度診療報酬を2026年6月以降の月にだけ適用します。過去月へ現行点数を遡及適用しません。対象期間は1月〜12月の暦年表示です。

歯髄状態とCAD材料区分が元データにないため、実績サマリーは下限〜上限で表示します。保険点数表では、生活歯/失活歯・CAD材料区分ごとに形成から装着材料までの内訳を掲載します。光学印象150点、装着材料38点、1点10円の試算です。

## リテーナー

「リテーナー」タブでは、セット数が4セットの症例だけを匿名集計します。上下4セットは8枚として、GCオルソリー、東洋デンタル、院内制作の直接原価と直接費控除後残額を比較します。

金額比較は上下4セット症例に限定し、上のみ・下のみ・歯列不明は件数だけに含めます。院内制作と東洋デンタルの直接原価差1,200円を判断ラインとして表示し、人件費、失敗、設備償却、廃棄、教育時間は金額へ加算せず技術負債として説明します。

## 技術選定

| 選択肢 | 判断 |
|---|---|
| HTML + JavaScriptのみ | 小規模には適するが、複数フィルター・3グラフ・状態管理の拡張性が弱いため不採用 |
| React + JavaScript | 実装可能だが、集計データの列変更を型で検知できないため不採用 |
| React + TypeScript + Vite | 採用。フィルター連動、コンポーネント分割、GitHub Pagesビルドに適する |

主なライブラリはReact、TypeScript、Vite、Recharts、Vitestです。

## 重要な公開ルール

元CSVには患者単位の情報が含まれます。元CSVはGitへ追加せず、ローカル変換で生成した`public/data/dashboard.json`だけを公開してください。担当医名・患者名・カルテ番号・患者単位行は公開しません。

公開JSONには以下だけが入ります。

- 月
- 日付基準
- 大分類・詳細種類
- 本数・未来予定本数
- 院内原価
- 外注相当額（成田デンタル・東洋デンタル）
- 保険点数・診療報酬額（下限・上限）
- 医院別の集計本数
- 月途中・未来月の状態
- リテーナーの月・医院別4セット症例数、上下比較対象数、既知制作枚数

## ローカル起動

```bash
npm install
npm run dev
```

## 実データの更新

元CSVを`data/raw/`へ置き、次を実行します。

```bash
npm run data:build -- --input data/raw/cerec.csv --as-of 2026-08-22
```

生成物:

- `public/data/dashboard.json`：GitHub Pagesへ公開可能な匿名集計
- `build-reports/data-quality-report.json`：ローカル確認用。除外理由と元CSV行番号

リテーナー管理CSVは、次を実行して匿名集計へ変換します。

```bash
npm run data:retainer -- --input data/raw/retainer.csv --as-of 2026-08-28
```

- `public/data/retainer.json`：月・医院別の匿名集計と原価マスター
- `build-reports/retainer-data-quality-report.json`：元ファイル名と集計件数を含むローカル確認用

集計ルール:

1. 部位数と補綴物数が同数なら1対1で展開
2. 補綴物が1種類で部位が複数なら同じ種類を各部位へ展開
3. それ以外は自動集計せず要確認へ除外
4. CAD/CAMアンレーはFDI歯式の末尾が4・5なら小臼歯、6・7・8なら大臼歯として判定

## 検証

```bash
npm run verify
```

検証内容:

- CAD/CAM冠・インレー、Zrの固定料金計算
- 実データの暫定基準値との一致
- その他を0円扱いしないこと
- 公開JSONのフィールドallowlist
- 本番ビルド
- ビルド成果物への元CSV列名混入チェック

## GitHub Pages

1. GitHubリポジトリを作成
2. `main`へコードを反映
3. Settings → Pages → Sourceで`GitHub Actions`を選択
4. Actionsの`Deploy GitHub Pages`を実行

Viteの`base`はGitHub Actions上で`GITHUB_REPOSITORY`から自動設定されます。
